# Certificate data and independent checks

Run these commands at the repository root with Python 3.10 or later. The default and `--check` modes read the archived outputs. To regenerate either output from verified inputs, replace `--check` with `--write`.

```sh
python3 -B research/audit/verify_t18.py --check
python3 -B research/audit/verify_graph_semantics.py --check
python3 -B research/audit/verify_written_obstructions.py
python3 -B research/audit/test_negative_controls.py
```

## Binary arrays

Each original JSON record has integer fields `strength` (`t`) and `columns` (`k`), with `1 ≤ t ≤ k`. The array `multiplicities` has `k+1` nonnegative integer entries in ascending weight order. Its element `x[i]` is the number of copies of **each individual binary word** of length `k` and weight `i`. The layer contains `comb(k,i) * x[i]` rows. The JSON type and value constraints for a single record are also supplied in [array-witness.schema.json](array-witness.schema.json). The verifiers additionally check the dependent length and marginal equations.

| Data | Contents and provenance | Reproduction |
| --- | --- | --- |
| [small.json](../../excess-arrays/small.json) | Array of stored witness records for strengths 1 through 16 | `python3 -B excess-arrays/verify.py excess-arrays/small.json` |
| [t18.json](../../excess-arrays/t18.json) | Single strength-18 witness, 36 columns. The stored vector can be regenerated by the original integer moment-rounding construction. SHA-256 of the original bytes is `3a47a3097137861a846d3bc62b72240cc96e6190831a978f4fd5cfd563cd6986`. | `verify_t18.py --check` reads the JSON directly. The separate `research/collect_results.py --check` also compares it with the original constructor. |
| [t18-residuals.csv](outputs/t18-residuals.csv) | Nineteen equations from the stored witness. All cells are arbitrary-precision base-ten integers. | `verify_t18.py --write` |

For row `i` of the CSV, `i` is the number of ones in the **specified 18-bit pattern**. The fields are `lhs = sum(comb(18,j)*x[i+j] for j in range(19))`, `rhs = factorial(i)*factorial(18-i)` and `residual = lhs-rhs`. The script separately checks positivity of every multiplicity, the minimum 350847, and the layer-weighted total of 121645100408832000 rows.

## Graphs

[graph-witnesses.json](outputs/graph-witnesses.json) uses schema version 1 and contains these two groups.

| Field | Meaning |
| --- | --- |
| `search` | One record for each of the four cases below. The original [exhaustive solver](../../packing-corona/graph_search.py) produces a complete SAT assignment or exhausts the search. |
| `search[].base_graph`, `n`, `k` | `path` or `cycle`, number of base columns, and allowed colors 1 through `k`. The corona has `3*n` vertices. |
| `search[].outcome` | `SAT` for an existing coloring or `UNSAT` after exhausting these assignments. |
| `search[].colors_by_column` | For SAT, a complete array of `n` triples. Triple `i` gives the colors of vertices `3i,3i+1,3i+2` in center, satellite, satellite order; numbering starts at zero. For UNSAT, the field is `null`. |
| `search[].search_nodes` | Number of search calls observed when producing that record. The semantic check reruns the search and prints its observed count. Acceptance depends on the result, and SAT additionally requires a valid complete coloring. |
| `published_cycle_13` | The eight-color construction of Sampathkumar, Sivakaran and Unnikrishnan as a complete assignment. Fields `source` and `colors_by_column` identify the publisher’s source and the coloring in the same vertex convention. |

| Base graph | n | k | Expected result | Evidence checked here |
| --- | ---: | ---: | --- | --- |
| Path | 11 | 6 | SAT | Archived assignment and freshly returned assignment |
| Path | 12 | 6 | UNSAT | Exhaustion of the original solver |
| Cycle | 13 | 7 | UNSAT | Exhaustion of the original solver |
| Cycle | 13 | 8 | SAT | Archived and fresh search assignments, plus the published assignment |

The BFS verifier builds each triangle from all three of its unordered vertex pairs. It joins centers in consecutive columns and adds the closing center edge for a cycle. For every vertex it computes a row of the distance matrix by breadth-first search. It then tests every unordered pair with matching color `c` for the strict inequality `distance > c`. It also checks all 25 ordered pairs of the five original construction blocks of lengths 6, 8, 15, 17 and 19, read from [verify.py](../../packing-corona/verify.py). The proof that arbitrary block concatenations work uses their common transfer state in the paper. The BFS pair checks provide additional finite cross-checks.

For the published assignment, the even-indexed centers take colors 4, 5, 6, 4, 5, 7, 8; the odd-indexed centers take color 1. The authors put `x_i` in color 2 throughout and give `y_i` color 1 on even columns and 3 on odd columns. Sorting the two interchangeable satellites in each column recovers the archived triples. This eight-color upper bound belongs to the original authors. The separate seven-color obstruction establishes optimality. [Sampathkumar, Sivakaran and Unnikrishnan, Theorem 3.1(ix), printed pp. 106–107](https://dergipark.org.tr/en/download/article-file/5580259#page=14)

For a negative result the original solver selects one unassigned vertex, branches on every currently possible color, and removes that color at vertices whose distance forbids it. An empty domain rules out the current branch. Swapping the two satellites in one triangle preserves distances, so requiring their colors to appear in increasing order covers one representative of every coloring up to those swaps. The archived JSON records the exhaustion outcome. The separate transfer algorithm recomputes the finite obstructions; the Lean graph project supplies a checked proof. The audit JSON contains no LRAT trace.

### Integer data for the written path obstruction

[path-weight-certificate.json](outputs/path-weight-certificate.json) transcribes the data in the [direct arithmetic proof](../../packing-corona/paper.md#direct-arithmetic-proof-of-the-two-finite-obstructions). The field `fixed_column` gives the zero-based index of the center whose color is fixed. Each of the four entries in `weights` contains twelve pairs in column order. A pair gives the center weight and the weight of **one** satellite. Each entry in `cases` gives the `fixed_color`, the `weights` label, the six `bounds` in color order and the `total` weight of all vertices. The sum of the bounds is derived. The verifier evaluates the printed recurrence and checks its bounds against color-class weights computed on the explicit graph. It also checks the equality constraints and parity calculation in the separate cycle proof. [Written-obstruction checker](verify_written_obstructions.py)

## Negative and positive controls

The control command creates files inside a temporary directory. It independently increments `x[0]` by one, replaces it with `−1`, and removes the last entry from separate copies of the original JSON. Both the original checker and the new integer audit reject each corruption. For the first mutation the equation at `i=0` acquires residual 1.

The graph control recolors the last center of the published witness from 8 to 4. The complete assignment still passes as a path, then fails as a cycle because its two end centers now share color 4 at distance 1. Both the BFS checker and the original cycle distance checker reject it. A positive control replaces the search-produced eight-color assignment by the published valid assignment and changes the stored node counts. The semantic audit accepts that temporary archive.
